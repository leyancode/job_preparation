# 性能指标、强扩展与统计

## 一、吞吐量

RepeatedSolves中有19次KSPSolve。若未知数为 `N`，KSPSolve最大时间为 `t`：

```text
Eq/s = N × 19 / t
```

这里使用PETSc各rank中的最大时间，因为并行程序必须等待最慢rank完成。

例如 `N=10,000,000`，19次求解累计用时2秒：

```text
Eq/s = 10,000,000 × 19 / 2
     = 95,000,000 equations/s
```

> [!warning]- 最常见的公式错误
> `t`累计了19次solve，分子也必须乘19。不能用 `N/t`，否则吞吐量被低估19倍。

## 二、每次迭代时间

若每次solve的KSP iteration count为 `k`：

```text
seconds/iteration = t / (19 × k)
```

它用于区分：

- 布局是否真正降低每次迭代成本；
- raw throughput优势是否只是少做了一次迭代。

它仍不是纯硬件指标，因为不同布局可能产生不同GAMG层次和每次迭代内部工作量。

## 三、Speedup与Efficiency

固定问题规模，节点数从 `P0` 增加到 `P`：

```text
speedup = T(P0) / T(P)

parallel efficiency = speedup / (P / P0)
```

如果只观察16到32节点的加倍：

```text
doubling efficiency = T(16) / (2 × T(32))
```

该效率只描述这一次相邻加倍，不能称为从1到32节点的整体效率。

例如某问题在16节点用时10秒，在32节点用时6秒：

```text
speedup = 10 / 6 = 1.67
doubling efficiency = 1.67 / 2 = 83.3%
```

## 四、强扩展与弱扩展

| 类型 | 固定什么 | 增加什么 | 当前研究 |
| --- | --- | --- | --- |
| strong scaling | 总问题规模 | 节点/核心 | 是 |
| weak scaling | 每核心问题规模 | 总问题规模和节点 | 不是主要设计 |

当前矩阵用 `25,000 ≤ unknowns/(nodes×128) ≤ 100,000` 选择可运行点，但每条scale曲线内部仍是固定总未知数的强扩展。

## 五、为什么可能出现超线性

超过理想线性的局部speedup不一定是错误。候选原因包括：

- 本地工作集进入更高层缓存；
- GAMG迭代数下降；
- 分区或粗层结构改变；
- 系统噪声与三次重复不足；
- 某个较小节点点异常慢。

必须同时检查iterations、seconds/iteration和event数据，不能把超线性直接归因于缓存。

## 六、三次重复能支持什么

每个正式配置有三次运行，图中使用：

```text
中心点：median
下界：observed minimum
上界：observed maximum
```

| 术语 | 含义 |
| --- | --- |
| median | 排序后的中间值；三个结果中取第二个 |
| observed range | 本次样本中实际观察到的最小值到最大值 |
| spread | `(maximum-minimum)/median`，表示观测范围相对中位数的宽度 |
| confidence interval | 依据统计模型估计总体参数可能所在的区间 |
| statistical significance | 在指定模型下，观察到的差异是否难以由随机波动解释 |

例如三次Eq/s为100、102和150，median是102，observed range是100–150。中位数不会被单个150直接拉到117.3，但三个样本仍不足以可靠估计总体分布或置信区间。

可以说：

- “三次运行的中位数为……”；
- “观测范围为……”；
- “两个布局的观测范围重叠/不重叠”；
- “最大spread为4.71%”。

不能说：

- “差异具有统计显著性”；
- “误差棒是95%置信区间”；
- “标准差证明结果稳定”，除非实际计算并报告标准差且样本设计合理。

> [!tip]- 接近点的补充实验
> 如果导师要求检验小差异，优先做5–10次paired/interleaved repeats。交错运行A、B、A、B可降低系统时间漂移对布局比较的影响。

## 七、跨2D/3D比较时增加的指标

Eq/s的“一个equation”在五点和七点矩阵中工作量不同。跨维度建议并列报告：

- Eq/s，表示应用吞吐量；
- seconds/iteration；
- MatMult time/iteration；
- PCApply time/iteration；
- flops/iteration或flop/s；
- messages和bytes/iteration；
- nonzeros/unknown。

## 自测

> [!example]- 为什么Eq/s公式的分子要乘19？
> `KSPSolve`时间累计了19次求解，分子也要表示19次处理的总equations。

> [!example]- observed range与confidence interval有什么区别？
> observed range只描述这三次实际结果的最小值和最大值；confidence interval需要统计模型，并试图估计总体参数的不确定范围。

> [!example]- raw throughput更高但seconds/iteration不低，说明什么？
> 优势可能来自较少的KSP iterations，而不是每次迭代执行得更快。
