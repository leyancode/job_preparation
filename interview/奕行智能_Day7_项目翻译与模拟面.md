## 1. 两分钟自我介绍（AI 芯片版）

> 我是爱丁堡 HPC 与数据科学硕士，课程和论文 8 月已完成，可以立即到岗。
> 我的核心能力是**在真实硬件上做可审计的性能归因**。硕士论文在 ARCHER2 上做了 4,096 核规模的并行布局实验：总核数固定，MPI 进程与 OpenMP 线程怎么切。结论是最优并行度随问题维度和每核工作量变化，2D 上 64×2 比纯 MPI 快 13.1%，3D 上 16×8 快 3.81 倍。更重要的是方法：我用 Linaro MAP 把利用率损失拆成「通信暴露」和「线程空转」两条反向变化的曲线，又在 PETSc 的事件日志上定义了一个零插桩、可累加的同步暴露指标，覆盖全部 264 个 run；审计时发现 302/303 份日志实际进程数与文件名不符，我作废了整个阶段的曲线，把内容校验写进分析入口。
> 第二个项目把 benchmark 数据做成可评测的 Agent 分析系统：LLM 只选工具和参数，数值由确定性代码算；规则路由 83.3%、LLM 100%，去掉 system prompt 掉到 63.3%；229 个测试全离线，CI 逐条复验 README 里的每个数字。
> 本科毕设是 PyTorch 上的多智能体强化学习，诊断出 MAPPO-QMIX 不收敛的根因是 TD 目标与 on-policy actor 不匹配。
> 我在 GPU / NPU 上没有生产项目，这是我清楚的差距；但「定位算力利用率、带宽、数据搬运和并行效率瓶颈，判断问题在模型、软件栈还是硬件」这件事，我在 CPU 集群上完整做过一遍，方法是可迁移的。我这周把 Transformer 推理的算子级性能、量化和 NPU 架构系统过了一遍，愿意从客户模型适配和性能分析做起。

（最后一段是「为什么从 CPU HPC 转 AI 芯片」的答案，主动说，不要等人问。）

## 2. 项目 → JD 语言映射（面试官照着 CV_ai_infra 问，你照着这张表答）

| CV 上的话 | JD 的话 | 面试里怎么说 |
|---|---|---|
| 同步暴露占比：叶子事件相加达 116–372%，只有 halo + 归约可加 | **并行效率瓶颈的定位**；性能指标的可加性 | 「profile 里的时间不能随便相加，我先证明哪些是互斥路径再加——在 NPU 上同理：DMA 忙与阵列忙重叠的部分不能算两次」 |
| MAP：MPI 46.7%→6.2%、OpenMP 等待 48.3%→76.5% | **算力利用率损失的归因**：通信 vs 同步等待 | 「布局排序就是两条曲线的交点；对应到芯片是『通信暴露』和『核间 / 流水空转』」 |
| 只读 MAP 占比排序、不与未插桩 timing 混用 | **性能分析工具的扰动意识** | 「插桩会改变被测对象，我把 profiler 数据只用于排序和归因，绝对数字用未插桩日志」 |
| 302/303 审计、408 run、13 项内容检查 | **自动化测试与数据可信度** | 「性能测试最容易出的错不是测慢了，是测的根本不是你以为的配置；我把校验写进入口，让管线自己拒绝错数据」 |
| 2D 64×2 / 3D 32×4、16×8，无单一最优线程数 | 「验证不同配置对性能的影响」 | 「结论绑定 workload 与 shape——量化 / tiling / 并行度的结论同样要绑定模型和形状」 |
| roofline / 访存墙估算（技能段） | 判断 compute / memory bound | Day 2 的公式 + H100 拐点 ≈ 295 |
| KV cache 与量化对每 token 访存量的影响（技能段） | decode 带宽瓶颈 | Day 1 §3：8B FP16 128 KB/token KV、单流上限 = 带宽 / 权重字节 |
| CUDA 编程模型、NCCL、数据 / 张量并行、batching（技能段，课程与自学） | GPU 并行执行原理 | Day 4 §2、§5；Day 5 §4；**先说「课程与自学层级」再答原理** |
| HPC_Agent：229 测试、CI 复验数字、trace 可回放、显式 unknown | PyTorch / Python 自动化测试与问题调试 | 「客户模型适配的回归测试我会这么建：golden + tolerance + 形状矩阵 + CI 断言头条数」 |
| MARL：TD 目标与 on-policy 不匹配、softplus(0)≈0.69 梯度放大 | **从模型异常定位软件栈问题** | 「训练不收敛不是调参问题，是目标定义错了；我从 loss 曲线的形状反推到代码里那一行」 |
| 论文里未解释的 superlinear、min–max 不是置信区间 | 科学诚信 | 「没证明的不写成结论」——芯片团队最怕的是把偶然当规律 |
