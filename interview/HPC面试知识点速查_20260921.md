## 2. 对着你的项目的高频追问（问法 → 答法）

**Q 为什么做 hybrid MPI+OpenMP？**
总核数固定时，减少 rank 数 → halo 消息数与 surface-to-volume 变小、allreduce 参与者变少、每 rank 内存/进程开销更低；代价是 OpenMP 的 fork-join、barrier、
spin-wait 与负载不均。问题是「省下的通信能否抵消线程成本」——答案取决于维度、规模和每核工作量。

**Q 为什么 2D 是 64×2，3D 却是 32×4 / 16×8？**
3D seven-point stencil 的 surface-to-volume 比 2D 大（局部块 n³ 的表面 6n² vs n² 的边 4n），每个 unknown 摊到的 halo 更多，减少 rank 的收益更大，
所以 3D 更偏向多线程。2D 里 16×8 去掉了最多同步暴露，但每个点都最慢——说明去掉的暴露还没「还清」线程空转的成本。

**Q 你怎么知道是通信换了线程空转，而不是别的？**
MAP call tree：MPI 占比 46.7%→6.2% 与 OpenMP 等待 48.3%→76.5% 反向变化；排除 threaded BLAS（LibSci ≤ 2.1%）。
但要主动说边界：`-log_view` 和 MAP 只能定位**开销在哪里被支付**，不能证明硬件机理（NUMA 靠拓扑排除，L3 需要 hardware counter 才能证明）。

**Q MAP 会扰动运行时间，你怎么处理？**
只读布局之间的占比排序，绝不与未插桩的 scaling timing 混用；正式吞吐数字全部来自未插桩的 `-log_view` 计时。

**Q 「同步暴露占比」是怎么算的？为什么不直接把所有事件加起来？**
`VecScatterBegin/End` 被 `MatMult` 调用、`SFPack/Unpack` 又嵌在 scatter 里，直接加叶子事件会得到 KSPSolve 的 116–372%。halo 和归约在互不相交的调用路径，
所以只有这两者之和合法。零插桩开销，264 个 run 全覆盖。

**Q 为什么按 unknown 数对齐而不是网格边长？为什么只计时 RepeatedSolves？**
同一线性系统规模下比较两种 stencil 的通信暴露才公平。GAMG setup（coarsening、prolongation）和稳态 solve 是两种成本，混在一起会让 setup 稀释结论；
warm-up 建层次，19 次 solve 复用 preconditioner，模拟时间步进/非线性迭代中「一次 setup 多次 solve」的真实场景。

**Q GAMG 迭代数随分区变化，怎么保证可比？**
同时报吞吐（equations/s）和 seconds per KSP iteration，把「迭代数、每迭代成本、总吞吐」三者分开看。
（细节：一个 CG step 在日志里是 `VecNorm`/`PCApply` = 19×13 = 247，比 12 次迭代多 1，因为 CG 先算初始残差。）

**Q 302/303 是怎么发现的？**
解析 PETSc header 里自报的进程数与文件名对比。教训写成分析入口的硬校验：进程 / 线程数只信日志内容、不信文件名。愿意作废整个阶段的曲线——这是数据洁癖的信号，主动讲。

**Q Superlinear speedup 怎么解释？**
如实：可重复观察到，但没确定硬件原因。假说是节点数增加后每 rank 工作集缩小到 16 MB L3 内，验证需要 perf / AMD uProf 的 L3 命中率与内存控制器计数器，
不是更多 wall-clock timing。**写为未解释项而非卖点。**

**Q 结论适用范围？**
绑定给定 stencil / solver / PETSc build / placement policy；3 次重复的 min–max 不是置信区间；不代表所有 PETSc 应用有相同最佳布局。

**Q 如果再做一次会加什么？**
hardware counters（L3、内存带宽）；NPS / 绑定策略变体；通信-计算重叠（MPI_THREAD_MULTIPLE、非阻塞 scatter）；更多重复次数；跨机器（如国产平台）复现。

**Q PETSc 里 OpenMP 线程具体在做什么？**（可能被追问，别编）
说清楚你的构建方式与 -log_view 观测到的事实；不确定的核（哪些 Mat/Vec 操作被线程化）就说「需要回去看构建配置」，不要现场猜。

## 3. HPC 通识高频知识点

### 3.1 加速比与定律（公式要能默写）

- 加速比 S(p) = T₁/Tₚ；并行效率 E = S/p。
- **Amdahl**（固定问题规模，strong scaling）：S = 1 / ((1−f) + f/p)，f 为可并行比例；上限 1/(1−f)。
- **Gustafson**（固定每核工作量，weak scaling）：S = (1−f) + f·p。Weak-scaling 效率 = T₁/Tₚ（理想为 1）。
- Karp–Flatt：用实测 S 反推串行比例 e = (1/S − 1/p)/(1 − 1/p)，e 随 p 增长说明并行开销在涨。
- 饱和点：每核工作量降到一定值后通信/同步占比压过计算；你的数据里各布局饱和点不同，饱和后排名反转。
- 你自己的例子：29.83×/32 = 93.2%；14.24×/32 = 44.5%。

### 3.2 MPI

- 基本：communicator / rank / size；`MPI_Init`（或 `MPI_Init_thread`）、`Send/Recv`、`Isend/Irecv/Wait/Waitall`、`Sendrecv`。
- 阻塞 vs 非阻塞；**eager vs rendezvous** 协议（小消息直接发进对方缓冲，大消息先握手）；`MPI_Send` 可能阻塞 → 两边同时 `Send` 会死锁，用 `Sendrecv`/非阻塞/奇偶交替解决。
- 集合通信：`Bcast`、`Reduce`、**`Allreduce`**、`Scatter/Gather`、`Alltoall`、`Barrier`。
  Allreduce 算法：小消息 recursive doubling（log₂P 步）、大消息 Rabenseifner / ring（reduce-scatter + allgather，带宽项 ≈ 2(P−1)/P·n/β）。
  → CG 每次迭代 2 次 `VecTDot` + 1 次 `VecNorm` 各一个 allreduce，随 P 增长以 log P 暴露，这就是「全局归约」那一项。
- α–β 模型：T(n) = α + n/β（延迟 + 消息大小/带宽）；很多小消息 → 延迟主导；合并消息、减少 rank 数减少消息数。
- Halo exchange：域分解后交换 ghost 层；1D 分解通信量 ∝ 边长，2D 分解 ∝ 边长/√P 更优；surface-to-volume：2D 4/n，3D 6/n。
- 通信-计算重叠：先 `Isend/Irecv` 边界，计算内部，再 `Wait` 后算边界。
- 线程支持级别：`MPI_THREAD_SINGLE / FUNNELED / SERIALIZED / MULTIPLE`；hybrid 常用 FUNNELED（只有主线程调 MPI）。
- 派生数据类型（`MPI_Type_vector` 发列/面）、`MPI_Comm_split`、Cartesian topology（`MPI_Cart_create/shift`）。
- MPI-IO / HDF5 并行 I/O（了解）。

### 3.3 OpenMP

- Fork-join 模型；`#pragma omp parallel` / `for` / `sections` / `single` / `master` / `task`。
- `schedule(static | dynamic,chunk | guided)`：static 开销最低、负载均匀用；dynamic 负载不均用，有调度开销。
- 数据作用域 `shared/private/firstprivate/lastprivate`；`reduction(+:sum)`。
- 同步：`barrier`（每个 parallel for 末尾隐含，`nowait` 去掉）、`critical`（互斥段）、`atomic`（单条更新，更轻）、`ordered`。
- **False sharing**：不同线程写同一 64B cache line 的不同变量 → 反复失效；用 padding 或每线程私有累加再归约。
- **First-touch**：页在第一次写入的线程所在 NUMA 节点分配 → 初始化也要并行且按相同分区。
- 绑定：`OMP_PLACES=cores|threads|sockets`，`OMP_PROC_BIND=close|spread|master`，`OMP_NUM_THREADS`；`OMP_WAIT_POLICY=active|passive`（spin vs sleep，对应 MAP 里的 `cpu_relax / do_spin / __futex_wait`）。
- 开销来源：并行区创建、barrier、spin-wait、负载不均、隐式同步；小 parallel region 太多（每个向量操作一个）→ 开销压过收益，这是 16×8 慢的一种解释。
- OpenMP 4.5+ `target` offload、SIMD 指令 `#pragma omp simd`（了解）。

### 3.4 Hybrid 怎么配

- 一个 rank 配一个 NUMA 域 / 一个 CCX / 一个 socket 是常见起点；线程不跨 NUMA。
- Slurm：`--ntasks-per-node=R --cpus-per-task=T`，`OMP_NUM_THREADS=T`，`--hint=nomultithread`（不用 SMT），`--distribution=block:block`（rank 连续占核），`--cpu-bind=cores`。
- 判断是否值得：通信占比高、每 rank 内存吃紧、集合通信随 P 变差 → 值得；计算密集且负载均匀 → flat MPI 往往不输。

### 3.5 体系结构与内存

- Cache 层级：L1（32 KB I/D）、L2（512 KB/核，Zen 2）、L3（CCX 共享 16 MB）；cache line 64 B；空间/时间局部性、分块（tiling/blocking）。
- **NUMA**：本地/远程内存延迟带宽不对称；`numactl --hardware`、`lstopo`、`numactl --membind/--cpunodebind`。
- 内存带宽：EPYC 7742 8 通道 DDR4-3200，每 socket 理论 ≈ 204 GB/s；STREAM 实测约 70–80% 理论。
- **Roofline**：性能 = min(峰值 FLOP/s, 算术强度 × 带宽)。SpMV / stencil / 向量操作算术强度 ~0.1–0.5 flop/byte → **内存带宽受限**；这就是为什么 CG 类求解器上「线程化」带来的收益有限、通信/同步才是主战场。
- SIMD：Zen 2 AVX2 256-bit，2 个 FMA 单元 → 16 DP flop/cycle/core；峰值 ≈ 16 × 2.25 GHz × 128 ≈ 4.6 TFLOP/s per node。向量化需要无依赖、连续访存、对齐；`-fopt-info-vec` 看报告。
- SMT / 超线程：内存受限代码通常关掉（`--hint=nomultithread`）。
- 互连：Slingshot（dragonfly 拓扑，每节点两块 100 Gb/s NIC）；InfiniBand（HDR 200 Gb/s）；延迟 ~1–2 µs 量级。
- 存储：Lustre（OST/MDT、striping）、GPFS；burst buffer（了解）。

NPS4 → 每 socket 4 个 NUMA 域、每节点 8 个、每域 16 核；每 socket 8 个 CCD、16 个 CCX、256 MB L3；Slingshot dragonfly；Lustre 文件系统。

### 3.7 数值方法

- **CG**：对 SPD 矩阵，每次迭代 1 次 SpMV + 2 次内积 + 3 次 axpy；收敛速率 ∝ √κ（条件数）；2D Laplacian κ = O(h⁻²) = O(N)，无预条件迭代数 ∝ 网格边长。
- **预条件**：Jacobi（对角）、**block Jacobi**（每 rank 一个块 + 局部 ILU/ICC → 块划分随 rank 数变，结果不可跨 rank 比较）、ILU/ICC、**AMG**。
- **AMG / GAMG**：setup（强连接图 → 聚合/coarsening → prolongation P → Galerkin 粗算子 PᵀAP）+ V-cycle（前光滑 → 限制残差 → 粗解 → 延拓修正 → 后光滑）；迭代数近似与规模无关（你的日志：12 → 10 → 6 次）。Setup 昂贵，所以一次 setup 多次 solve 的 RepeatedSolves 设计有意义。
- **GMRES**：非对称也能用，restart(m) 控内存；MINRES / BiCGStab（了解）。
- 稀疏格式：CSR/AIJ（PETSc 默认），SpMV 每非零 ≈ 12 B（8 B 值 + 4 B 列号）做 2 flop → 内存受限；PETSc 的 `MatMult` 拆成本地部分 + off-diagonal 部分，off-diag 需要 `VecScatter` 取 ghost 值。
- Stencil：2D five-point 每点 5 非零，3D seven-point 7 非零；有限差分与已知解误差校验（manufactured solution）。
- PETSc 对象：`Vec / Mat / KSP / PC / DM(DMDA)`；`-log_view` 报 Count、Time、Flop、Messages、Reductions；`-ksp_monitor`、`-ksp_converged_reason`。
- 浮点：并行归约顺序不同 → 结果不逐位一致；double vs float；稳定性 vs 精度。

### 3.8 性能分析方法论与工具

- 先测再猜：hotspot → 归因（计算 / 通信 / 同步等待 / I/O）→ 模型（roofline、α–β）→ 改 → 回归验证。
- 工具：`-log_view`（PETSc 自带事件计时）；**Linaro MAP / DDT**（采样 + call tree，会扰动）；`perf stat/record`（硬件计数器，PAPI）；`gprof`；Score-P + Vampir / Scalasca（trace）；TAU；Intel VTune / Advisor（roofline）；AMD uProf；`likwid-perfctr / likwid-bench`；`mpiP`（MPI 占比）；STREAM / HPL / HPCG 基准。
- 度量纪律：中位数 + 观测范围；多次重复；warm-up；不混插桩与未插桩数据；把头条数锁进测试防漂移。
- 常见优化：减少通信次数与 rank 数、合并消息、重叠、避免 barrier、改善局部性（blocking）、向量化、消除 false sharing、first-touch、负载均衡。

## 4. 可能的白板题（模式）

1. **OpenMP 求和**：`#pragma omp parallel for reduction(+:s)`；追问「不用 reduction 怎么写」→ 每线程私有累加 + `critical` 或数组 + padding 防 false sharing。
2. **MPI halo exchange**：`MPI_Irecv` 左右 → `MPI_Isend` 左右 → 计算内部 → `MPI_Waitall` → 计算边界；边界 rank 用 `MPI_PROC_NULL`；周期边界用 `MPI_Cart_shift`。
3. **为什么会死锁**：两边都先 `MPI_Send` 大消息（rendezvous）；改 `Sendrecv` 或奇偶序或非阻塞。
4. **矩阵乘/转置分块**：cache blocking 提高复用；解释 i-k-j 顺序访存连续。
5. **π 数值积分 / 蒙特卡洛并行**：MPI reduce；随机数种子按 rank 区分。
6. **给一段慢代码找问题**：内层循环跨 stride 访存、循环内分支、false sharing、每次迭代开 parallel region、`dynamic` 调度粒度太细。
7. **估算题**：给定带宽和算术强度估算 SpMV 上限；给定 α、β 估算 allreduce 时间；给定 Amdahl f 估算最大加速比。
8. **Python 侧**：pandas 聚合 + 中位数；解析日志用正则；写一个 pytest 断言头条数。
